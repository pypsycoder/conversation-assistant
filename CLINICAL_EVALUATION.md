# Методика оценки

Версия 1, 08.11.2026. Данные только синтетические. Эталоны автора-агента требуют
независимой врачебной проверки. Это исследовательские показатели, не клиническая приёмка.

`examples/nightly-v1/manifest.json`: diagnostic d01–d03 (12 критериев), validation
v01–v02 (5), final f01 (2). Final резервный, но не независимо ослеплённый:
автор набора видел все примеры. Не оптимизировать по final; для настоящего закрытого
контроля нужен набор от независимого врача. Старые gold и оценки не меняются.

Новая точка отсчёта — существующий прямой `SYSTEM_V2` / `three_sections.SCHEMA`.
Это отдельный воспроизводимый reference, НЕ замена принятой инкрементальной S.
Сравнение с S требует отдельного адаптера и свежих одинаковых входов.

Перед API хешируются код, промпт, схема (в коде), источники и gold. Gold никогда
не передаётся модели. Источник содержит роли и условный порядок; секунды фиктивные,
их нельзя интерпретировать как аудиотайминг.

Оценщик заполняет review-template для КАЖДОГО пункта трёх разделов. Указывает
полностью и частично сохранённые gold ID, число необоснованных атомарных утверждений,
ошибок отрицания, времени и источника, а также объяснение. Цитата сама по себе
не доказывает смысловую поддержку текста. Дополнительные верные факты вне gold
требуют отдельной версии рубрики и пересчёта ОБЕИХ веток, не молчаливого FP.
Составные критерии должны быть полностью сохранены; частичная передача не TP.

TP = число уникальных полностью сохранённых критериев. FN = gold − TP.
FP = частичные критерии, нигде не переданные полностью, плюс необоснованные атомы.
Precision = TP/(TP+FP); Recall = TP/gold; F1 = 2TP/(2TP+FP+FN).
Это строгая полнота клинических критериев; критерии пока не все атомарны.
Не представлять эти числа как универсальные метрики атомарных фактов.
При нулевом знаменателе показатель null. Дубли и неверное распределение считаются
отдельно: один факт в жалобах и анамнезе болезни допустим по рубрике, две одинаковые
пары факт/раздел — дубль. Показывать покрытые/обязательные и правильные/предсказанные
размещения, исходные TP/FP/FN и количество диалогов.

Измеряются API-секунды, полное время, prompt/completion/total tokens. Рубли null до
настройки фактического тарифа; нельзя выдавать токены за стоимость. Token reserve
консервативный по UTF-8 входа + max_tokens, не провайдерский финансовый лимит.

Счётчик принимает только проверку с SHA текущего gold и ответа. Не использовать
оценку самого GigaChat как единственное доказательство. Оценка Codex тоже не врачебная
и не слепая. Принимать кандидата после свежего парного сравнения: никаких новых
необоснованных утверждений/ошибок отрицаний/времени/источника, потерь обязательных
критериев или роста дублей; затем проверочная группа и повторы. При спорном смысле
статус awaiting_physician_review, автоматического продвижения нет.
