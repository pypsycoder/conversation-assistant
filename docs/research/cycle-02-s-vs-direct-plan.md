# Цикл 02 — готовая S против прямого извлечения

08.11.2026. Прямое поручение пользователя: одинаковые синтетические диалоги,
полнота, выдуманные факты, три раздела; Git и следующий исследовательский шаг.
План и рубрика фиксируются до новых API-вызовов.

## Условия

- d01–d03 из examples/nightly-v1: 3 диалога × 4 ответа пациента, 12 составных
  критериев, 15 обязательных размещений. Исходные gold/диалоги не меняются.
  Набор диагностический, уже известен автору, не слепой и не врачебно утверждённый.
- D: существующие three_sections.SYSTEM_V2 и SCHEMA, полный диалог за один запрос.
- S: неизменные prompt/schema reported_by, окно до 5 предыдущих ходов, текущий
  ответ и активная память; wire-ID adapter, S.apply_patch с R1, E1-events/repair/fixed,
  печать print_v3 из цикла 01. Исторический reducer/промпт не правим.
- Одни и те же тексты, роли и исходные ID, без gold в запросах. Контексты различаются
  по архитектуре: D видит всю беседу сразу, S — только префикс и память.
- Модель GigaChat-3-Ultra, temperature 0.001, max_tokens=5000 на запрос в обеих
  ветках, один повтор. При изменении возвращённой ревизии — остановка.
- Свежие обе ветки; старый D из нулевой итерации не используется как новый контроль.
  Порядок: d01 D→S, d02 S→D, d03 D→S. Оцениваем конечный результат обеих веток.
- 15 генераций максимум: D 3, S 12. До 300000 возвращённых токенов с консервативной
  резервацией до вызова, до 20 минут плюс максимум 120 секунд начатого HTTP.
  Общая блокировка runner; прямой HTTPS с проверкой TLS. Рубли неизвестны.
- Ошибка схемы/patch — зарегистрированный отклонённый шаг, не новый запрос.
  При неизвестной квитанции/расходе остановка без повтора. Не отбрасывать неудачные
  случаи из знаменателей. Никаких автоматических ремонтов сверх штатной S.

## Оценка

Старый построчный scorer непригоден для честного сравнения: S делит один критерий
на несколько свойств. Здесь каждый gold-критерий оценивается по объединению
всех связанных строк результата, а полнота раздела — по строкам конкретного раздела.
Не требовать дозу и длительность в одной строке S. Противоречащий актуальному
значению старый текст не считать полной передачей исправленного критерия.

Для каждого критерия: full / partial / missing / distorted, ссылки на строки,
полностью покрытые разделы и объяснение. Для каждой выходной строки отдельно:
поддержка исходником, новые неподтверждённые атомы, ошибки источника/времени/отрицания.
Дословность цитат не доказывает смысл. Верные дополнительные сведения вне gold
не считать выдумкой. Одинаковое выдуманное утверждение в нескольких разделах
учитывать один раз по смысловому ID, размещения — отдельно.

Показать full/12, partial/missing/distorted, обязательные полные размещения/15,
правильные/все распознанные размещения и число неподдержанных смыслов/строк.
Strict criterion P = full/(full+partial+distorted+unsupported_unique),
R = full/12; F1 с указанными TP/FP/FN. Это составные критерии, не атомарная F1.
Также указать дубли, source/time/polarity errors, API-время, полное время и токены.
Оценщик Codex, не GigaChat, не врач, не слепой. Gaps/unresolved — отдельная
диагностика, их нельзя выдавать за правильность трёх разделов.

## Решение и продолжение

Одна пара из 3 коротких диалогов — диагностика, не доказательство превосходства.
Не переключать default. Выявить конкретные потери, проверить их по сырому ответу,
адаптеру, реестру и печати. Затем выбрать один минимальный обоснованный опыт:
при программном дефекте — offline regression/replay; при ошибке модели — новая
гипотеза до следующих вызовов. Не повторять отклонённый общий редактор.
Сохранить исходники, запросы, ответы, оценки, freeze, отчёт и отдельный PR.
